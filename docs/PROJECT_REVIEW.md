# 智慧查询：详细项目复盘

> 本文聚焦需求演进、工程取舍与问题定位。功能总览、架构图和运行方式请先阅读仓库 [README](../README.md)。

## 背景与目标

业务团队过去主要通过 Excel 或人工询问查找总成编号、商品名称与测试编码。随着资料增长，查询效率、版本同步、权限控制和操作追溯逐渐成为问题。

项目的目标不是简单把表格搬进小程序，而是建立一条可管理的资料访问链路：员工先注册并经审核，通过保密确认后查询；维护能力按角色或单项授权开放；关键行为保留审计记录。

## 需求如何拆解

需求被拆为四条可分别验证的主链路：

1. **准入链路**：注册、待审核、通过或拒绝、保密确认。
2. **查询链路**：按总成编号或商品名称搜索、展示多个结果、一键复制。
3. **维护链路**：型号增删改与批量导入、图片槽位管理、普通员工的细粒度授权。
4. **治理链路**：三级角色、服务端鉴权、管理员配置和操作日志。

这种拆分让每轮修改都能围绕一个清晰场景进行编译和真机验证，降低跨页面回归风险。

## 工程设计取舍

### 统一云函数入口

小程序端通过 `wx.cloud.callFunction` 调用单一 `api` 云函数，由 action 分发业务请求。`users`、`models`、`operation_logs` 等集合的读取与修改集中在服务端，避免把敏感数据访问能力交给客户端。

### 权限不仅是隐藏按钮

页面会按当前角色调整入口和控件，但这只是交互层。云函数会重新识别当前用户，并在敏感 action 执行前检查角色或细粒度权限。普通员工默认只能查询；管理员可单独授予其上传型号图片或编辑总成编号的能力；管理员角色的授予与取消仅由超级管理员执行。

### 图片使用固定槽位

每个型号最多维护 5 张图片。固定槽位使新增、替换、删除和展示顺序更可预测，也便于服务端验证图片与型号之间的绑定关系。

### 公开版本与真实环境隔离

作品集保留结构、业务流程和虚构 Demo 数据，不保留真实 AppID、云环境 ID、OpenID、员工资料、日志、Excel 或公司型号数据。环境相关内容使用示例配置和部署文档表达。

## 典型问题定位

### 1. 旧云环境导致启动异常

- **现象**：项目导入后无法正常进入业务流程。
- **定位**：代码版本本身并非唯一变量，开发者工具关联的云环境和客户端初始化配置同样影响启动。
- **解决**：逐项核对项目绑定、环境选择与初始化配置；公开版本只保留空配置或示例，避免误连真实环境。
- **复盘**：小程序云开发问题应先区分代码错误、工具配置和远程环境状态，再决定修改范围。

### 2. session 与权限缓存不一致

- **现象**：超级管理员或管理员进入管理页时，界面能力与账号真实权限不一致。
- **定位**：部分页面依赖此前缓存的用户信息，角色变更后没有及时刷新；服务端状态与前端展示发生偏差。
- **解决**：关键管理页面重新请求 session 并刷新全局用户状态；真正的权限控制仍由云函数执行。
- **复盘**：缓存适合提升体验，不应成为授权依据。界面展示可以短暂滞后，敏感操作的服务端校验不能缺失。

### 3. 微信好友分享不可用

- **现象**：查询首页无法按预期分享给微信好友。
- **定位**：对照正式页面与微信页面生命周期后，确认查询页缺少页面级分享处理。
- **解决**：在查询页补齐好友分享生命周期，保持修改局部，并通过开发者工具和真机复测。
- **复盘**：涉及微信客户端行为时，静态阅读只能缩小范围，最终仍需要真机验证。

### 4. 微信审核与员工注册流程冲突

- **现象**：平台审核需要可访问路径，但真实员工账号又必须经过注册和管理员审核。
- **定位**：审核账号与正式员工使用相同应用入口，却具有不同的访问生命周期和数据边界。
- **解决**：设计可关闭、可轮换的审核访问机制，服务端控制有效性，客户端不保存审核凭据。
- **复盘**：审核便利不能绕过正式权限模型；临时入口必须可撤销、可隔离，并避免接触真实数据。

## AI 协作边界

开发者负责提出业务目标、解释真实流程、操作开发者工具、执行真机测试并验收结果。ChatGPT 用于梳理需求和风险，Codex 用于在本地仓库实施范围明确的修改、检查差异和运行测试。

AI 没有替代产品判断或测试责任。一次典型迭代是：开发者描述现象并提供截图反馈，AI 帮助形成假设和最小变更，开发者再通过编译与真机结果决定是否进入下一轮。

## 收获

这个项目让我把微信小程序生命周期、云开发、服务端鉴权、角色权限、操作审计和数据脱敏放进同一个真实业务链路中理解。更重要的是，它形成了一套可复用的方法：先明确现象和权限边界，再做最小修改，最后用开发者工具、真机和业务规则共同验证。
