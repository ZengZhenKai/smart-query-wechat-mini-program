# 项目复盘

## 项目背景

业务团队过去主要通过 Excel 或人工询问查找总成编号、商品名称与测试编码。数据增长后，查询效率、权限控制和操作追溯逐渐成为问题，因此实现了“智慧查询”微信小程序。

## 需求拆解

系统被拆为四条主链路：员工注册与审核、保密确认与查询、型号及图片维护、角色权限与日志审计。页面负责交互，云函数负责身份确认、权限判断和数据访问。

## 架构

- 微信原生小程序负责页面与交互。
- 单一 `api` 云函数按 action 分发业务请求。
- `users`、`models`、`operation_logs` 分别承载身份权限、型号资料和审计记录。
- 服务端执行权限校验，前端权限展示仅改善体验。
- 云存储保存型号图片和用户头像。

## 开发与版本迭代

项目从查询主流程逐步增加注册审核、三级权限、保密确认、型号维护、图片槽位、日志和好友分享。每轮根据开发者工具与真机反馈定位问题，尽量采用局部、可验证的修改。

本作品集标记为 1.0.5，对应已经完成并验证“分享给微信好友”的功能状态。原项目未保存 1.0.5 Git tag；作品集版本依据真实项目文件和开发记录制作，并移除了此后用于朋友圈分享排查的临时诊断代码。

## Bug 排查实例

- 云环境关联错误导致启动异常。
- 注册完成后的 session 状态与页面跳转不一致。
- 管理页使用缓存身份，造成超级管理员能力显示异常。
- 查询页未声明页面级分享生命周期，导致好友分享菜单不可用。
- 审核环境与真实员工注册流程需要隔离。

## 我在项目中的工作

- 梳理业务角色、页面流程和数据边界。
- 实现并验证注册审核、查询、型号维护、图片管理和日志功能。
- 将关键权限判断放到云函数，补充安全规则与自动化契约测试。
- 使用微信开发者工具和 Android 真机完成交互与分享问题排查。
- 按公开作品集标准清理配置、历史数据和内部资料。

## AI 协作方式

由开发者提出业务目标和测试反馈，ChatGPT 协助拆解需求与风险，Codex 在本地项目执行精确修改、静态检查和测试。最终结果仍通过开发者工具、真机和业务规则人工确认。

## 项目收获

这个项目强化了我对微信小程序生命周期、云开发、服务端鉴权、角色权限、审计日志、数据脱敏以及最小化调试方法的理解，也形成了一套“需求—实现—验证—反馈—迭代”的工程流程。
